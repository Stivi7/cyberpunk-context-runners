# Task Classification

## Metadata

- Version: 1.0.0
- Triggers: New task intake or material scope change
- Allowed agents: Nexus
- Side effects: Creates or updates local task state

## When to Use

Use before assigning work and repeat when discoveries materially change risk. Do not classify by line count alone.

## Inputs

Task objective, acceptance criteria, repository context, uncertainty, reversibility, operational impact, and authority.

## Procedure

1. Choose **quick** only for localized, reversible, established-pattern, low-risk work.
2. Choose **complex** for architecture, cross-stack contracts, security, migrations, destructive potential, or high uncertainty.
3. Choose **standard** for everything between those bounds.
4. Record evidence for the choice and the roles required.
5. Upgrade the route when new risk appears; never downgrade merely to save time.

## Verification

Confirm every identified risk has an owner and the selected route includes all required gates.

## Output

Workflow level, rationale, participating roles, required skills, and reclassification triggers.
